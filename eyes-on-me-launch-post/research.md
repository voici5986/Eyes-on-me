# Research

## Topic Statement

为 `Eyes on Me` 写一篇中文项目介绍文章，风格偏标题党、强钩子、适合公众号/博客平台传播，但内容必须基于项目仓库里现有信息，不虚构功能。

## Audience Assumptions

- 独立开发者
- Rust / 桌面工具 / 自我量化爱好者
- 对“注意力流失”“时间去哪了”有强烈共鸣的人
- 喜欢能落地、能运行、能看到界面的项目介绍文章的读者

## Research Scope

仅使用当前仓库里的本地资料，不做外部检索。

重点确认：

- 当前页面结构
- 前后端职责
- 支持的平台和采集方式
- 项目现在强调的核心价值
- 是否已有截图资源可插入文档

## Key Facts And Takeaways

1. 项目当前页面只保留三个主页面：
   - `/` 首页 / 全局分析页
   - `/devices/:deviceId` 单设备明细页
   - `/devices/:deviceId/analysis` 单设备分析页

2. 项目核心链路是：
   - 桌面采集端读取前台应用、窗口、浏览器上下文
   - 服务端持续写入 SQLite
   - Vue 页面做首页 / 明细 / 分析展示

3. 首页现在不再是单纯入口页，而是直接承担“全局分析”角色。

4. 单设备分析页有 treemap，但 treemap 现在只用于“应用层”，不混入域名层。

5. 浏览器相关信息仍然会单独进入“域名累计”统计。

6. 项目支持时间范围切换：
   - `3h`
   - `6h`
   - `1d`
   - `1w`
   - `1m`
   - `all`

7. 技术栈确认：
   - Rust
   - axum
   - tokio
   - sqlx
   - SQLite
   - Vue 3
   - Vite
   - TypeScript
   - vue-router
   - SSE

8. 平台采集实现确认：
   - macOS: `NSWorkspace`
   - Windows: `SetWinEventHook`
   - Linux: `xprop` 轮询

9. 仓库里已经存在可引用截图：
   - `image/Home.png`
   - `image/Detail.png`
   - `image/Analyze.png`

## Important Background Context

- 这个项目的传播角度不应该写成“企业监控”或“团队管控”，因为当前仓库表达更偏向自我观察、自我复盘。
- 标题党可以强调“时间消失”“以为在工作”“浏览器一开 3 小时没了”这类强共鸣切口。
- 文章应该把“它不是抽象效率评分，而是把实际使用轨迹摊开”作为核心卖点。

## Possible Article Angles

### Angle A

“我原以为自己只是查个资料，结果 3 个小时没了”

适合做强情绪开头，拉高共鸣。

### Angle B

“我做了个 Rust 项目，专门拆穿自己到底在电脑上干了什么”

适合开发者受众，强调项目动作和技术实现。

### Angle C

“这不是监控软件，这是给自己做的一台时间 CT”

适合偏传播型标题，但正文要更克制。

## Working Title Direction

主标题方向选择：

“我原以为自己只是开了个浏览器，结果 3 小时没了：我做了个 Rust 项目，把自己的时间流失一刀切开”

原因：

- 有强钩子
- 有明确冲突
- 能自然带出项目动机
- 兼容技术读者和普通读者

## Outline

1. 强情绪开场：时间为什么会“突然没了”
2. 项目动机：不是为了监控别人，而是为了先抓出自己
3. 项目做了什么：采集、落库、展示
4. 首页为什么重要：它不是入口，而是结论
5. 单设备明细页的价值：看切换链条
6. 单设备分析页的价值：应用层 treemap + 域名累计
7. 为什么用 Rust 单体来做
8. 这个项目最真实的地方：它不帮你美化
9. 总结与适用人群
